# Wine-фиксы поверх официальной HDT 1.58.6

Рабочая версия — `1.58.6.9003`. Это официальный exe с локальными изменениями IL и трёх BAML-ресурсов. Остальной код 1.58.6 и все DLL взяты из официального full-пакета. В частности, сохранены новые подписки Tier7 на обновление данных аккаунта и выход из него.

Исходный коммит выпуска `484c3dfabdd1b640ff486d9b3ab9fce908230474` указан в официальном PDB, но пока отсутствует в публичном репозитории. Поэтому исходники публичного `master` `b8f67044d5d02a85e7ad7bf4e8b14da8dd30d36e` используются только для получения методов с локальными фиксами. Собранный из них exe нельзя устанавливать вместо официального 1.58.6: 16 исходных файлов отличаются.

Перед переносом `Weave.cs` сравнивает методы официального exe с чистой сборкой публичной базы. Разрешены различия в путях диагностических сообщений и номерах автоматически сгенерированных классов. Несовпадение исполняемого кода выбранного метода останавливает перенос. Сравнение включает `MoveNext` всех затронутых async-методов. Новые вспомогательные классы получают суффикс `__HdtWine`; существующие классы остаются на месте.

Конструктор `BattlegroundsSessionViewModel` сохраняется из официальной версии. В него добавляются только инициализаторы двух списков истории игр. Его новые обработчики `HSReplayNetOAuth.AccountDataUpdated` и `LoggedOut` остаются подключёнными.

## Состав

- `Program.cs`, `Weave.cs`, `weaver.csproj` — перенос методов и выгрузка/загрузка ресурсов через Mono.Cecil 0.11.6.
- `MergeBamlResources.cs` — заменяет три BAML-записи через .NET Framework ResourceReader/ResourceWriter и проверяет сохранность остальных 403 записей.
- `PrepareWineMethods.cs` — проверяет загрузку и подготовку изменённых методов и вспомогательных классов под Wine/.NET.
- `weave-audit.json` и `binary-verification.json` — список изменений и результат сравнения всех оригинальных методов.
- `jit-verification.log`, `regression-tests.log` — успешные проверки загрузки 75 методов и шести существующих регрессионных тестов.
- `source-verification.json` — сравнение SHA-256 исходников из официального PDB с публичной базой.
- `result.json` — хэши официального пакета, исходного и исправленного exe, архива и манифеста.

## Воспроизведение

Готовый архив `../artifacts/hdt-working-v1.58.6-recent-games.tar.zst` не требует сборки. Для повторного переноса нужен Linux .NET SDK 8, Windows .NET SDK 8 под Wine, .NET Framework 4.7.2 reference assemblies и C# compiler для `MergeBamlResources.cs`. Окружение этой машины находится в `$HOME/.cache/hdt-build`.

1. Скачать `HearthstoneDeckTracker-1.58.6-full.nupkg` из [официального выпуска](https://github.com/HearthSim/HDT-Releases/releases/tag/v1.58.6), проверить SHA-256 `8b33dbb35f050413c01c3d3f8773f685e599f3657d51c6cf62dc4cc87c79233e` и распаковать. Оригинальный exe имеет SHA-256 `3a7a11aa7b779fbb6bcbb328bc39f2a9ad78c18b1a5daa818364b4ea7be2716b`.
2. Подготовить два чистых дерева публичного коммита `b8f67044`. В одно применить `../hdt-wine-functional-v1.58.6-donor.patch`. Оба собрать с официальными DLL 1.58.6, параметрами `Release`, `Platform=x64`, `Version=1.58.6`, `BuildNumber=9003` и одинаковыми временными Wine-правками сборки. Не устанавливать эти exe.
3. Собрать `weaver.csproj`. Через `HDT_CECIL_REFERENCE_DIRS` передать разделённые двоеточием каталоги .NET Framework reference assemblies и официальных DLL, чтобы Cecil мог определить типы значений по умолчанию. На этой машине использованы `prefix/drive_c/windows/mono/mono-2.0/lib/mono/4.7.2-api`, его `Facades` и официальный `unpacked/lib/net472`.
4. Вызвать `weaver.dll weave <официальный-exe> <exe-с-фиксами> <чистый-публичный-exe> <woven-exe>`. Выгрузить `HearthstoneDeckTracker.g.resources` из официального exe и exe с фиксами командой `weaver.dll resources <exe> <output.resources>`.
5. Скомпилировать `MergeBamlResources.cs` под .NET Framework и запустить с тремя аргументами: официальный `.resources`, `.resources` с фиксами, выходной `.resources`. Вставить результат командой `weaver.dll attach <woven-exe> <output.resources> <patched-exe>`.
6. Создать полный каталог-кандидат из официального `lib/net472`, заменить exe и его имя на `Hearthstone Deck Tracker.exe`, переименовать `.exe.config` аналогично. Добавить `System.Resources.Extensions.dll` из сборки. Удалить `HearthstoneDeckTracker.pdb`: он относится к исходному exe и не соответствует новым metadata tokens. PDB неизменённого HearthWatcher сохраняется.
7. Проверить кандидата изолированным `hdt-prelaunch.py`, запустить `PrepareWineMethods.exe` против исправленного exe и существующие тесты истории игр/кнопок из `HDTTests` против него же. Сравнить все методы официального и выходного exe: изменены ровно 18 оригинальных методов, добавлены 57, остальные 25 681 совпадают. Все официальные DLL должны совпадать побайтно.
8. Сделать резервную копию текущей установки, snapshot и пользовательских данных. Установить кандидат с сохранением `Plugins/`, запустить guard и HDT. При горячей замене держать lock `hdt-overlay-restart.lock`, чтобы автоматический recovery не вмешивался в замену файлов.

Подготовка двух деревьев сохранена в `$HOME/.cache/hdt-build/v1.58.6/{baseline,donor}/{prep.sh,build.sh}`, установка — в `deploy.py`. Архив содержит 174 файла и не содержит пользовательского Roaming-каталога, токенов или игровых записей пользователя.
